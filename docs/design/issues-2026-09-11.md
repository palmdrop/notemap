# General
- monospace font is too stiff
- dual font looks bad - move to uniform font
- bad hierarchy, unclear sections
- need stronger separators (grid, dividers), bold and capitalized text. Try to still stick to the same font size everywhere
- background color off-white should be pure white
- text color should be pure black

- theme switcher should be moved to settings
- "online" indicator" should just be a simple icon
- "NOTEMAP" text in the top left corner can be removed 
- top navbar should have links to action log

- more fluidity - at the moment, we have not designed for transitions, flow, animations, etc - using notemap feels very unpolished

# Queue/Feed
- "Anything worth keeping" as the template text in the capture input should be removed
- Capture input needs to be more dinstinct: a clear input box
- "not captured" beside capture input should be removed
- "unrouted" can be removed, as it is implied by the presence of an item in the queue
- "+" sign for tags is unclear. Another way to indicate tags is needed
- grey background as highlight for selected capture is ugly
- square action buttons should be part of a more distinct grid, visible when clicking a capture
- add captures into a grid, with a vertical line separating date sidecar from capture content
- double-clicking should open a capture
- routing tags are way too long > when shown as tags they should not show an arrow pointing at the template name, they should just be styleized differently 

# Composer
- composer is messy and cluttered
- since composer offers rewrites, tagging, statistics about routing, etc, we might want to reconsider if it is just a modal?
- destination sections are needed, it is not clear which are destinations, which are templates and which are manual
- "discard" is called "archive"/"unarchive" in some places (concept has been renamed in composer only)
- "used before" list in composer is way too long. Should only show a short list of latest items, with a number of routes to the destinations at the top. Or maybe not even be shown at all.
- tags in composer take up too much space. Unused tags should not show, only used ones.
- "words" just repeat what is at the top
- "rewrite" button reads as part of the capture contents
- rewrites should happen in place, where the acutal capture contents is shown, at the top of the composer
    - for long captures, and image captures, we need to reconsider design. What happens when the user edits and expects to see the entire capture body?
- "would write" is meaningless unless the destination/template actually auto-rewrites/formats the content
- composer needs a layout change. Preview and edit needs more space. Not everything has to be visible at once. Some sections can be collapsed, only shown if user actually needs them.
- composer should never scroll in its entirety, instead, sections within the composer are allowed to scroll. The "route" button at the bottom should always be visible.

# Routing records
- looking at a routing record is confusing - there is no heading, no clear way of determining that this is a routing record
- "where it landed" is a strange wording
- it is not visually clear that the "where" indicating the destination is related to "where it landed", the path or location inside the destination
- "where" should be "destination" and location/placement within that location should be adjacent
- "item" link should not show content, instead opening the capture item should be a button press, not the content text, since content will be shown in the record output anyway
- date of the routing record is good to have, but the date and time is so related to the capture itself, would maybe be good if the capture took up more space in the design
- "what was sent" is too long, should just be "content" or "output"
- "its tags did not go" should be removed, just show the content
- visually, the destination + location + output should be ordered in a logical way, like we are viewing a file with a title and a path
- "the decision" is irrelevant for a user, this information should not be visible 
- routing records show the contents of the file itself, but not potential assets - it should be clear where assets landed
- routing records do not properly render images. It is more important to a user how the content looks than what the exact markdown content is. Seeing the raw content could be available behind a button press.

# Capture view (opened item) 
- tags read strange, like the capture row
- routing tags, again, are too long and does not need to point to the template
- routing record lines should be shown in a simple grid on the side. Long file names needs to be truncated somehow, or the routing record grid should be expandable

# Log
- design should be a grid with the action type clearly visible in a row
- "Everything the pool has done..." text can be removed
- source label can be removed
- routing log entries show too much information
    - user does not care about IDs
    - template should not show the id of the template, but the name, with a link
    - "firedByTag" is not really relevant to a user
    - "pointer" reads strange, should be "path" or "location" or "place"
    - log entry for routing records should use the same design/layout/component as opening a routing record does
- log needs a filter to show only a certain action type. The most common use case will be to inspect a list of routing records, since that is the main function that Notemap performs.
- log items should clearly indicate 1) when it occured but also 2) which item they refer to. "about" is vague, it is not clear that this refers to an item
- "only this" button is unclear, needs to be renamed somehow. Although, it is nice to have the ability to see all log entries about a specific capture item

# Settings
- "what the pool can reach, and where it keeps things" can be removed
- "pool" wording is not necessarily clear to the user, they just see the feed and the queue
- "sources" might be a stale concept, at least for the user. Maybe it can still be there, but hidden. Most of the time, it is not relevant.
- "daemon" is a vague concept for a user. Perhaps "server"?
- "session" as a section is not really justified since it only has "sign out". Perhaps an "Account" section where we add a sign out button, but also access tokens. In the future, we could also add a way of changing password there.
- each section should be accessible from a side menu with the section title
