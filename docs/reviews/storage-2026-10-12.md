**Status**: Resolved

**Plan**: `docs/plans/what-notemap-takes-on-disk.md`

## Overall

The shape is right and the seam ADR 60 drew is held everywhere: nothing outside a driver knows
about `-wal`, shard directories or a `.md` beside a `.json`, and `statfs` lives in the daemon.
Decision 4 — the figure a person presses and the reclaim they fire reading one predicate — is real
in the code (`pastGrace`) and pinned by tests at three levels. Typecheck, `pnpm -r --silent test`,
`pnpm lint` and `pnpm test:stack` are all green; the only `pnpm -r lint` failure is
`apps/raycast-extension` failing to `mkdir /home/node/.config/raycast`, which is environmental and
predates this branch. Every one of the five specs carries a dated `Shipped:` entry, and the plan's
Done status is honest.

One figure is wrong, and it is wrong in the specs as well as in the code: **`X saved by holding
identical bytes once` subtracts the whole blob store from the asset registry, and the blob store
holds routing-record outputs and blobs nothing names besides the blobs assets point at.** Finding 1.
Everything else is small.

## Bugs

### 1. `saved` is not what content addressing saved

`apps/ui/src/components/settings/Storage.svelte:88` — `held.assets.bytes - walked.blobs.bytes`,
drawn as `18 MB saved by holding identical bytes once`.

`assets.bytes` sums the `assets` table. `blobs.bytes` sums *every* blob in the store, and the store
holds three kinds: blobs an asset names, blobs a routing record's output names
(`packages/core/src/pool/routing/output.ts:87` puts delivered content straight into
`ports.blobs`, with no `assets` row), and blobs nothing names at all. So with dedup savings `S`,
output bytes `O` and unnamed bytes `U`:

```
saved = S − O − U
```

A pool that has delivered anything that kept a copy understates the saving by the output bytes; a
pool with no dedup and some outputs computes a negative, which `saved > 0` hides by drawing
nothing — so the failure is silent in both directions. The branch's own UI fixture shows it:
`apps/ui/src/components/settings/Storage.test.ts:31` has 715 KB of unnamed blobs inside
`blobs.bytes`, so the asserted `18 MB saved` is already ~715 KB short of the registry's real
saving, and the test asserts the wrong number as correct.

The specs state the same arithmetic — `docs/specs/http-v1.md:806` and `docs/specs/core.md`'s
`recorded()` bullet both say "the difference is what content addressing saved" — so this is a doc
change and a code change together.

Fix: compute the saving where the registry is, not by subtracting a different population.
`assetsHeld` can answer it in the same cheap query it already runs — `SUM(bytes)` over `assets`
minus `SUM(bytes)` over `SELECT DISTINCT blob, bytes FROM assets`, which `assets_blob`
(`migrations.ts:229`) already indexes. That figure is exactly "the same bytes under two names cost
once", needs no walk, and leaves `measured.blobs` free to mean what it says: everything on the
disk. Failing that, stop claiming a saving and draw the two totals side by side.

## Design

### 2. The deployment line asserts containment for any string an operator declares

`apps/ui/src/components/settings/Storage.svelte:209` draws
`rest="the paths above are inside the container"` whenever `deployment` is present.

`deploymentOf` takes `NOTEMAP_DEPLOYMENT` verbatim from the environment
(`apps/daemon/src/storage/deployment.ts:30`) — only the `/.dockerenv` fallback and this repo's own
`Dockerfile` guarantee a container. An operator running the daemon under systemd who sets
`NOTEMAP_DEPLOYMENT=nixos` to label the row gets told their absolute host paths are inside a
container, which is the one thing the deployment line exists to say truthfully. The daemon is
careful here (declared, never inferred, absent where nothing says); the shell then throws that care
away by hardcoding the conclusion.

Either the sentence belongs to the two values the daemon can vouch for, or the daemon should answer
containment as its own flag rather than leaving the shell to read it off a free-text label.

### 3. `bytesOf` swallows every error, so an unreadable auth database reads as no auth database

`apps/daemon/src/storage/storage.ts:113-119` — bare `catch { return undefined }`, and `live()` then
omits the `auth` key entirely.

`freeAt` next door distinguishes `ENOENT` from everything else and the two adapters' footprint
helpers do the same, each rethrowing what it did not mean to handle. Here an `EACCES` on a
`config.auth` that is definitely configured produces a report that silently has no auth row — the
one shape the type reserves for "this daemon holds no database". A person diagnosing why the auth
row vanished has nothing to go on. Match the neighbours: `ENOENT` is nothing, anything else throws.

## Minor

### 4. The cheap read is fired and discarded on every look after the first

`apps/ui/src/components/settings/Storage.svelte:41-47` — `if (mine === look && held === undefined)`.
The read exists to draw something before the walk lands, so from the second `reread()` (after a
reclaim, or after the pool comes back) its answer can never be used, and the request is pure cost.
Guard the call rather than the assignment.

### 5. `took` is never cleared

`Storage.svelte:19` — `took 2 blobs, 714 KB` stays drawn through every later measurement and across
the pool going out of reach and back, with nothing saying how long ago it was. `reread()` clears
`said` and not this.

### 6. The full-stack suite asserts a deployment absence it does not control

`tests/full-stack/src/storage.test.ts:63` — `expect(...deployment).toBeUndefined()` on a daemon
spawned without the variable. That daemon calls `deploymentOf()` with the real
`existsSync("/.dockerenv")`, so the assertion fails on any machine whose suite runs inside a
Docker-built container. The daemon fixture takes exactly this care —
"what the machine running the tests is must not reach an assertion",
`apps/daemon/src/testing/fixture.ts:143` — and the full-stack test undoes it. Passes here and on a
GitHub VM runner; it is a trap for anyone running the suite in the project's own container.

### 7. The attachment total counts attachments it did not measure

`apps/ui/src/components/item/AttachedLines.svelte:25-43` — the sum skips an attachment whose
`bytes` is absent (`packages/client/src/capture/attachments.ts:11`: unknown until the pool answers
or the store holds it), but the line still says `{attachments.length} attachments`. An item with
one landed attachment and one still unknown draws `2 attachments, <one attachment's bytes>`. Count
what was summed, or say nothing where any is unknown.

### 8. The daemon's pool path is a duplicated literal in the fixture

`apps/daemon/src/testing/fixture.ts:174` and `:211` both write `join(stateRoot, "pool.db")`. They
agree today; a test asserting `report.pool.path` would stop meaning anything the moment they don't.

### 9. `storage.stop()` is not awaited where the other stops are

`apps/daemon/src/main.ts:164` — `storage.stop()` aborts and returns, while `reclaiming.stop()`
(`:168`) deliberately awaits its in-flight walk before `pool.close()` (`:170`). A measurement in
flight at shutdown is aborted and unwinds inside four awaited stops, so in practice it is gone
before the pool closes; the worst case is a 500 on a request that was already going to be cut off.
Worth a line saying why this one does not wait, since the file's neighbour says why it does.

## Non-issues

- **`$effect` writing the `asked` flag it reads** (`Storage.svelte:76`) — identical to
  `Server.svelte:81`, and it converges on the second run.
- **Bodyless `POST`s under `requireJsonBody`** — `declaring` in `packages/client/src/api/http.ts:19`
  sets `content-type` on every write without one, so the client's `measure()` and `reclaim()` pass
  the media-type gate.
- **A reclaim leaving `measured` stale** — stated on the route
  (`definitions.ts`, `reclaimRoute.description`), tested, and the shell re-measures. Invalidating it
  in the service would make the reclaim own the cache, which decision 6 declined.
- **One `blobNamed` per blob in `measure`** — the same N+1 `reclaimUnnamedBlobs` already runs over
  the same store, which is what keeps the two reading one rule.
- **`POST /v1/reclaim` outside `/v1/storage/*`** — decision 2: it is a pool operation a storage
  surface happens to fire.
- **Handlers returning the service's object without validating it against `storageSchema`** — house
  pattern (`routes/counts.ts`); the schema is the published description, not a gate.
- **`measured.at` as `z.string()`** — no schema in `apps/daemon/src/schemas/` uses
  `z.string().datetime()`; this is the convention.
- **`readdir(root, { recursive: true })` materialising the whole mirror tree before the first
  `throwIfAborted`** — the plan's open unknown about the walk's cost, left deliberately.
- **The database's free pages answered on the wire and drawn nowhere** — decision 10, and the UI
  test asserts the absence.

## Resolution

1. **Fixed.** The registry answers the saving itself. `PoolReads.assetsHeld` returns
   `{ count, bytes, saved }`, `saved` being its summed bytes less the bytes of the blobs it names
   counted once — one more expression in the query it already ran, over the `assets_blob` index.
   `RecordedStorage.assets` carries it, `GET /v1/storage` publishes it, and the section draws it from
   the cheap read instead of subtracting the walk, so the figure now arrives without waiting for the
   measurement. An integration test builds a pool with both a shared blob and a delivery's output and
   asserts the saving while asserting that the old subtraction is *not* it. Specs changed with it:
   `core.md`'s reconciliation bullet, `http-v1.md`'s `assets` bullet, `shell.md`'s assets row, a
   dated amendment on [ADR 60](../adr/0060-a-driver-answers-how-much-it-holds-and-the-host-owns-the-paths.md)'s
   consequence, and decision 14 on the plan.
2. **Fixed.** `deploymentOf` answers `{ name, contained }`. The name is still whatever the image
   declared; `contained` is the marker alone, which is the only part a daemon can check. The shell
   draws *the paths above are inside the container* only where `contained` is true, so an operator
   labelling a bare-metal daemon gets the label and no claim about their paths. The wire shape of
   `deployment` changed with it, and so did `http-v1.md` and `shell.md`.
3. **Fixed.** `bytesOf` rethrows anything that is not `ENOENT`, with a test that a path which cannot
   hold a database at all throws rather than reading as a daemon holding none. `freeAt` is left
   swallowing: whether a filesystem answers `statfs` at all is a different question from whether a
   configured file can be read.
4. **Fixed.** The cheap read is fired only where nothing is drawn yet.
5. **Fixed.** What a reclaim took is handed to the look that follows it, so the line and the figures
   it explains arrive together, and any later look drops it. Tested across the pool going out of
   reach and back.
6. **Fixed.** The suite asserts the declared name, and for an undeclared daemon only that it says
   nothing or no more than `container` — whichever the machine running the suite makes true.
7. **Fixed.** The total is drawn only where every attachment can say its size, so the count and the
   figure are always about the same attachments. Tested with one attachment the pool has not
   answered for yet.
8. **Fixed.** One `poolFile` in the fixture, used by both `openPool` and the storage service.
9. **Fixed.** `Storage.stop()` awaits its in-flight walk, as `Reclaiming.stop()` does, and `main.ts`
   awaits it — the asymmetry is gone rather than explained.
